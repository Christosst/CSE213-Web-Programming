Chapter 30: Razor Pages and UniversityWeb

Complete the backend picture with a server-rendered .NET 10 website. UniversityApi returns JSON; UniversityWeb returns HTML. Use the browser to demonstrate Razor Pages.

Run the project locally

Open UniversityWeb to use the Razor Pages browser demo. The deployment pipeline publishes it at /universityWeb/ with the same database as /universityAPI/. For local practice, start both apps below.

dotnet run --project Demos/UniversityApi --launch-profile classroom
dotnet run --project Demos/UniversityWeb --launch-profile classroom

Open http://localhost:5083/. Run the two commands in separate terminals, starting the API first. Both apps use Demos/UniversityApi/App_Data/university.db, including the CSE213 cohort and the full university catalogue. A Swagger change appears here after refreshing, and a Razor save appears in the API.

Follow one page request

  1. Open Students and read Index.cshtml.cs: OnGetAsync loads data.
  2. Read Index.cshtml: Razor renders the student rows as HTML.
  3. Create a temporary student and inspect the POST form values in DevTools.
  4. Submit missing or duplicate data; observe errors and preserved input.
  5. Save valid data; follow POST → redirect → GET.
  6. Find the same student in Swagger, edit it, and refresh the Razor page.
  7. Enroll the student in CSE213. Remove the enrollment before deleting the student.

30-minute practice

Require a student name to contain 2–80 characters. Add an enrollment count to the student Details page. Test rejected and accepted input, then explain where C# runs. No database schema change is needed.

EF Core scope: model, query, save. Authentication, migrations and advanced application architecture are later topics.
