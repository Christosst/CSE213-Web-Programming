University SQLite CRUD

A university database with course sections: one teacher teaches several courses; students join courses through enrollments.

Teacher → Course ← Enrollment → Student

Run locally

dotnet run --project Demos/UniversityApi --launch-profile classroom

University API home · Open Swagger · ER diagram and classroom walkthrough

Use the API README for the extended ER diagram, local import instructions and the CSE213 class roster queries. The deployed API includes the full student roster and course catalogue.

Demonstrate in Swagger

  1. POST a teacher and a student. Keep their returned IDs.
  2. POST a course using the teacher ID.
  3. POST an enrollment using the student and course IDs.
  4. GET lists, GET one record, and GET the two relationship queries.
  5. PUT each record and show its updated values.
  6. Try a duplicate enrollment (409) and an unknown course ID (400).
  7. Try deleting a course with an enrollment (409).
  8. Restart the API: the SQLite records remain.
  9. DELETE the enrollment, then the student and course, then the teacher.

Each of the five entities (students, teachers, courses, sections and enrollments) has five operations: GET list, GET by ID, POST, PUT and DELETE. EF Core only connects the models to SQLite and defines keys and relationships.
