## Changes that make the sequence easier to teach

- Begin with one working concept. Main HTML/CSS examples avoid decorative interface code and long comments.
- Keep native form validation before custom JavaScript. The fuller registration lab is separate from the three-field teaching example.
- Use a known practice average, a three-product module example, and a task board matching the DOM lab. The inventory lab can extend the product data to five items.
- Use deterministic local fetch fixtures for loading/success/empty/error. The slides' username search is extension work; chapter 29 supplies the real REST integration.
- Teach hello and Swagger before CRUD, then a text form before the larger task frontend.
- Keep SQLite/EF Core in a separate optional app. Both assignment choices retain validation, Swagger and frontend integration.

Timing in chapter notes is for the demonstration and student activity only. It does not include lecture explanations, installation or assignment support.
